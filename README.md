# jj-squash-hunk.nvim

> [!WARNING] AI Warning
>
> This is generated by AI, so take it with a grain of salt.

Squash the hunk under the cursor — or every hunk overlapping a visual selection —
from the jj working change into its parent change.

## Why

jj has no staging area, so "I have reviewed this hunk" has nowhere to go. The
manual answer is `jj squash -i`, picking the hunk in a diff editor, which costs
several keystrokes per hunk. This plugin does it in one: the reviewed hunk moves
into `@-`, the rest stays in `@` as work in progress.

## Requirements

- Neovim >= 0.12 (`vim.text.diff`, `vim.fs.relpath`)
- [`jj`](https://jj-vcs.github.io/jj/latest/) on `$PATH`
- optional: [jj.nvim](https://github.com/NicolasGB/jj.nvim) — its open `jj://`
  diff buffers are refreshed in place after a squash
- optional: gitsigns.nvim — refreshed after a squash when it is installed

## Install

### lazy.nvim

```lua
{
  "RicardoRyn/jj-squash-hunk.nvim",
  lazy = true,
  cmd = "JJSquashHunk",
  keys = {
    { "<leader>gs", "<cmd>JJSquashHunk<cr>", desc = "Squash hunk" },
    { "<leader>gs", ":JJSquashHunk<cr>", mode = "x", desc = "Squash selection hunks" },
  },
  opts = {},
}
```

### vim.pack

```lua
vim.pack.add({ "https://github.com/RicardoRyn/jj-squash-hunk.nvim" })
vim.keymap.set("n", "<leader>gs", "<cmd>JJSquashHunk<cr>", { desc = "Squash hunk" })
vim.keymap.set("x", "<leader>gs", ":JJSquashHunk<cr>", { desc = "Squash selection" })
```

## Usage

| Command              | Action                                             |
| -------------------- | -------------------------------------------------- |
| `:JJSquashHunk`      | squash the hunk under the cursor into `@-`         |
| `:'<,'>JJSquashHunk` | squash every hunk overlapping the visual selection |
| `:5,12JJSquashHunk`  | squash the hunks overlapping lines 5-12            |

Lua API: `require('jj_squash_hunk').squash_lines(first, last)`.

## Configuration

```lua
require("jj_squash_hunk").setup({
  diff_context = 0, -- vim.text.diff ctxlen
})
```

`diff_context` controls how a change is cut into hunks. The default `0` makes each
hunk a maximal block of contiguous changed lines, which matches what gitsigns-style
signs show. Larger values merge changes separated by at most `2 * diff_context`
unchanged lines into a single hunk.

## How it works

1. The buffer is written, since jj snapshots the file from disk.
2. The parent version of the file is read with `jj file show -r @-` and diffed
   against the current content with `vim.text.diff` (the builtin xdiff engine, so
   no diff parsing).
3. The hunks overlapping the cursor line or selection are applied to the parent
   version, producing the content the parent should end up with.
4. `jj squash -i --from @ --into @- -- <path>` runs with a scripted one-shot diff
   editor that writes that prepared content to `$output`. Whatever lands in
   `$output` is squashed; everything else stays in `@`.

## Notes

- A file first added in `@` is handled: the absent parent version is treated as
  empty, so squashing a hunk creates the file in `@-` with just those lines.
- Deleted lines count as hunks too; like gitsigns, a pure deletion belongs to the
  line before and after the removed range.
- Only the current buffer's path is passed to `jj squash`, so a squash always
  touches exactly one file.
- Unsaved changes are committed to disk before squashing; the command refuses to
  run in non-file buffers (including jj.nvim's revision views).
